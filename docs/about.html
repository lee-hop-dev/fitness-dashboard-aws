System architecture

Two paths through the system

Writes happen once a day on a schedule. Reads happen on every page load. Keeping them separate is the single most important decision in this architecture — it means a normal visitor never touches compute at all.

Scheduling Compute Storage Delivery Security Primary read path Fallback / scheduled write
What happens each morning

The daily run, step by step

Nobody presses anything. The whole sequence below completes in about a minute and a half, every day, and finishes by writing a single pre-aggregated file that the site reads directly.

06:00:00
EventBridge fires the scheduled rule
A managed cron rule invokes the collector Lambda. No server, no scheduler to maintain, and nothing to keep running between invocations.
06:00:30
Lambda pulls credentials, then calls Intervals.icu
The API key is read from Secrets Manager at runtime — never committed, never in an environment variable. Intervals.icu is the authoritative source for every training metric on this site.
06:01:00
Activities, wellness and curves land in DynamoDB
Three tables on on-demand billing: activities, daily wellness (CTL, ATL, TSB, HRV) and power, pace and HR curves. No provisioned capacity means no idle cost.
06:01:05
Per-activity streams written to S3
Second-by-second power, heart rate, cadence and GPS for the last 14 days, plus lap splits and Strava segment achievements, stored as static JSON.
06:01:07
One aggregated dashboard.json replaces eight API calls
The last step bundles every payload the site needs into a single file. Page load went from eight API Gateway round-trips and roughly 726 KB to one cached fetch of about 320 KB — and the read path stopped touching Lambda entirely.

Under the hood

The parts a visitor never sees

The dashboard is the thin layer on top. The engineering that matters runs silently, keeping the data fresh, the infrastructure reproducible and the spend bounded.

Automated daily sync

Every morning the collector fetches up to 400 days of activity history, daily wellness metrics and multi-sport performance curves, then writes them to DynamoDB and S3 — with no human in the loop.

EventBridge · Lambda · DynamoDB · S3
No credentials in the codebase

There are no API keys, tokens or secrets anywhere in source or in environment variables. Every credential is fetched from Secrets Manager at runtime, and IAM roles grant access to named ARNs only.

Secrets Manager · IAM · least privilege
Everything is in code

All seven stacks are TypeScript CDK, backed by CloudFormation. The whole platform can be torn down and redeployed from the repository in minutes, because no part of it was configured by hand.

AWS CDK · CloudFormation · TypeScript
Seven live alarms

Lambda error rates and throttles, API Gateway 5xx responses and DynamoDB throttling are all watched in real time and wired into an operations dashboard, so a fault announces itself.

CloudWatch · alarms · ops dashboard
An actual kill switch

One POST request disables the EventBridge schedule, scales DynamoDB to zero and pauses the CloudFront distribution. It exists so a runaway cost has a floor rather than a ceiling.

Lambda · EmergencyShutdownStack · Budgets
One source of truth

FTP, power curves, running bests and CTL/ATL/TSB all come straight from Intervals.icu. Nothing is recalculated in the browser or the Lambda — a rule held across every phase, because two sources of a number means two answers.

Intervals.icu · API-first · no derived metrics
